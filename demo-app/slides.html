SB005 管理者API
attacker $ curl https://demo-app.example.com/api/admin/users # Authorization ヘッダーなし、認証なし HTTP/1.1 200 OK {"users":[{"id":"001","name":"田中 太郎","email":"tanaka@example.com", "role":"admin","password_hash":"$2b$10$xJ8mNpQ3vL..."}, ...5件のユーザー情報]}
👉 demo-app/attack.html で攻撃シミュレーターを確認

ツール不要

curl 1行、またはブラウザのアドレスバーだけ

ログイン不要

アカウントを持っていなくても実行できる

痕跡が残りにくい

通常の HTTP リクエストと区別がつかない

1つの穴から始まる被害の連鎖

攻撃シナリオ
1

GET /api/admin/users — 認証なしで全ユーザー取得（SB005）

メールアドレス・ロール・パスワードハッシュが流出

2

パスワードハッシュをオフラインでクラック

bcrypt でも弱いパスワードは数秒〜数分で解読される

3

console.log のトークンを使って管理者になりすます（GN001/GN002）

サーバーログにアクセスできる立場なら即座に悪用可能

4

DELETE /api/admin/users — 全ユーザーデータを削除

もしくはフィッシングメールを全ユーザーに一斉送信

Claude Code で一括修正

修正後 Critical 0件
修正前
// ❌ 認証なし export async function POST(req) { const { title } = await req.json() await supabase.from("posts").insert(...) } // ❌ fallback secret const secret = process.env.JWT_SECRET || "fallback-dev-secret" // ❌ ログ出力 console.log("token:", token)
修正後
// ✅ 認証チェック追加 export async function POST(req) { const member = await verifyMemberToken( extractToken(req) ) if (!member) return 401 await supabase.from("posts").insert(...) } // ✅ 起動時にエラーで検知 if (!process.env.JWT_SECRET) throw new Error("JWT_SECRET is required")
